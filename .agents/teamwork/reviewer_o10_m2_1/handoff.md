### B. Code Inspections
1. **Critical Defect in QR Format Information Encoding (`src/lib/qrSiswa.ts` lines 269–291):**
   ```typescript
   // 7. Format Information (Level L, Mask 0: 0x77a5)
   const formatBits = 0x77a5;
   for (let i = 0; i < 15; i++) {
     const bit = ((formatBits >> (14 - i)) & 1) === 1;
     if (i < 6) {
       matrix[8][i] = bit;
     } else if (i === 6) {
       matrix[8][7] = bit;
     } else if (i === 7) {
       matrix[8][8] = bit;
     } else if (i === 8) {
       matrix[7][8] = bit;
     } else {
       matrix[14 - i][8] = bit;
     }

     if (i < 8) {
       matrix[size - 1 - i][8] = bit;
     } else {
       matrix[8][size - 15 + i] = bit;
     }
   }
   ```
   - In ISO/IEC 18004 Section 8.9 (Table 10), the 15-bit format sequence for Error Correction Level L (`01`b) and Mask 0 (`000`b) masked with `101010000010010` (`0x5412`) is `111011111000100` (`0x77c4`), NOT `0x77a5`.
   - In ISO/IEC 18004 Table 10, Module `(8, 0)` is assigned bit 0 (the Least Significant Bit, LSB), module `(8, 1)` is bit 1, up to module `(0, 8)` which is bit 14 (MSB).
   - In `qrSiswa.ts`, bit assignment evaluates `(formatBits >> (14 - i)) & 1` which traverses in reverse order (MSB to LSB).
   - Reading the format modules generated by `generateQrMatrix` produces bits `0x52f7`. The Hamming distance between `0x52f7` and the true ISO Level L Mask 0 pattern (`0x77c4`) is **7 bit errors**.
   - Because BCH(15, 5) code can only correct up to 3 bit errors, standard QR decoders (hardware 2D USB HID scanners, phone cameras, ZXing, jsQR) fail to recognize Mask 0 or misclassify the format as Mask 1 (`0x72f3`, Hamming distance 2). When de-masked with Mask 1 instead of Mask 0, every data codeword is corrupted into invalid data (`[217, 10, 138, 117, 37]`), completely breaking real-world scanning.
   - When corrected to `const formatBits = 0x77c4;` and `const bit = ((formatBits >> i) & 1) === 1;`, standard QR decoders read the data with 0 errors and decode the exact ASCII text.

2. **Wildcard Vulnerability in `resolveStudentByCode` (`src/lib/qrSiswa.ts` lines 400–406):**
   ```typescript
   let queryIl = supabaseClient
     .from('data_siswa')
     .select('*')
   ```

   PostgREST interprets `%` and `_` as wildcard operators. If a scanned string or search term contains `%`, `ilike` matches unintentional records.

3. **Unescaped HTML in Print Modal (`src/components/AdminDataView.tsx` lines 867, 895, 936):**

## 2. Logic Chain

1. Requirement R2 states: *"Setiap siswa memiliki QR code unik yang di-generate sistem SIPJAM... mendukung scan kamera browser maupun hardware scanner eksternal... menghasilkan presensi datang atau pulang"*.
2. When students present printed QR badges or show digital QR codes, physical barcode scanners and camera readers parse the 15 format information bits to determine the mask pattern and error correction level before de-masking data modules.
3. Because lines 270–271 of `src/lib/qrSiswa.ts` contain an incorrect format constant (`0x77a5` instead of `0x77c4`) and inverted bit indexing (`14 - i` instead of `i`), the generated matrix diverges by 7 bits from the ISO 18004 standard.
4. Because the error exceeds the BCH(15, 5) 3-bit correction capability, standard 2D hardware scanners and camera decoders will fail to read the printed cards.
5. While unit tests in `tests/qrSiswa.test.ts` passed, they were self-certifying (only checking matrix dimensions and SVG tag existence without attempting decoder de-masking or format verification).
6. Therefore, the implementation in `src/lib/qrSiswa.ts` cannot be approved until this defect is corrected.
